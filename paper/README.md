# IEEE paper

Official IEEEtran conference class and IEEE BibTeX style—no layout modifications—inform main.tex. Fields for author and affiliation are all only placeholders. The three app screen shot placeholders are there on purpose. This is a thorough prototype/scenario analysis manuscript, not evidence that the actual physical tests have been successfully finished.

From `paper/` one can create the paper by running `tectonic --keep-logs --reruns 2 main.tex` or `pdflatex main && bibtex main && pdflatex main && pdflatex main`. Left as they are, the official `IEEEtran.cls` and `IEEEtran.bst` official files have their license notes transferred from CTAN into the package. Tectonic is quite fast since it will just download the other dependencies it requires on its first network-enabled build. Fixed repeats have been done to help us prevent a Tectonic 0.15 bibliography change detection warning (change detection in the last logs is what we are depending on). The paper is `main.pdf`. Every item mentioned in `references.bib` has undergone verification; the two owner provided records in `supplied_unverified.bib` are incomplete and we are not asserting they have been referenced in any capacity.

From the root of the repository, run `MPLCONFIGDIR=/tmp/privacy-paper-mpl simulation/. venv/bin/python paper/generate_architecture.py` to create an architecture diagram. The images of the geometry/simulator are relocated from `analysis/generated/` and `simulation/generated/` into `paper/figures/` so that the LaTeX source package may be developed apart from those folders. Without measurements, future calibration will have to be carried out using the `calibration_template.csv` sheet. All original observations ought to stay apart from the configuration of the trial scene. `SOURCE_VERIFICATION.md` details all source scope and checks boundaries.

The text also provides the auth extension source and integration report: Android Mobile FaceNet (prototype threshold determined from enrolment, PIN PBKDF2 parameters and retry cooldown), and the option to let the user remain signed in. At a real Android location (i.e. an Android store where a client would have their product), there is still no way to check an Android phone to be physically real. We provide no empirical data on latency, energy, biometric performance or calibration outcomes.
